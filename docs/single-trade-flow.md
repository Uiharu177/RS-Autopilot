# 单次端点跑商全过程（当前逻辑）

本文说明当前代码在两城市端点跑商（例如 `岚心城 → 海角城`）时，
一次完整回合实际会执行的顺序、确认条件和失败处理。

文档描述的是当前本地实现，不是理想化设计。坐标只是实现细节；是否
执行下一步仍以页面 OCR、货舱数量和场景验证为准。

## 一、启动与接管

任务开始后，脚本首先：

1. 确认模拟器已启动并连接设备。
2. 确认游戏在前台；若游戏未启动则启动游戏。
3. 启动接管将游戏恢复到可读取的主界面或城市界面。
4. 识别当前城市。

启动期间的特殊界面处理：

- 每日签到奖励：识别到底部“触碰空白区域退出”后，点击左上空白处关闭；不会点击奖励格子。
- 资源包更新：识别“需要下载资源 / 资源包 / 下载资源”后点击“确认”，然后等待加载，不会在同一轮继续点登录。
- 网络加载层：底部固定状态区出现随机的“正在……”文字时，归为加载中；暂停点击底层页面，等待该层消失后重新识别。
- 网络不佳对话框：识别“当前网络不佳，请尝试重新连接”后点击确认重连。确认后若仍有底部加载层，只等待；若对话框再次出现则再次重连。连续完成五次重连后仍再次出现网络错误时，保存诊断、停止任务并关闭游戏。
- 登录页：仅在没有更新、网络对话框或加载层覆盖时，才点击登录入口；若页面未变化，以短周期重试。

如果启动恢复最终无法到达可读页面，任务以失败结束，不开始跑商。

## 二、确定起始城市与清货

以当前识别城市为起点。端点路线 `A → B` 的运行策略是：

- 当前在 `A` 或 `B`：先进入该城交易所卖货页，尝试处理已有货物；随后从当前城市开始第一轮。
- 当前不在路线城市：执行归位流程；卖货、买货、前往路线首城，再开始正式回合。

### 进入交易所

1. 主界面优先在右下固定小区域 OCR “访问城市”。
2. 城市页面动态 OCR 查找任何包含“交易所”的店名。
3. 命中店名时，点击**完整 OCR 文本中心向下偏移**的位置。
4. 成功进入后，以“城市 + 门店”缓存点击点；再次同城使用缓存时必须先验证页面，失败即删缓存并回退动态 OCR。

交易所存在三类页面，切换顺序严格区分：

| 当前页面 | 前往买货页 | 前往卖货页 |
|---|---|---|
| 纯交易所入口页（中部大按钮） | 点击中部“我要买” | 点击中部“我要卖” |
| 已在卖货页 | 点击底部“我要买”页签 | 不点击，直接确认成功 |
| 已在买货页 | 不点击，直接确认成功 | 点击底部“我要卖”页签 |

实际买卖页的专属 OCR 标记优先级高于“我要买 / 我要卖”文字。
因此卖货页底部自带的“我要买 / 我要卖”页签，不能再被误认为交易所入口页。

若点击页签后没有确认目标页，返回失败；不会退回去反复盲点入口页按钮。

## 三、卖货流程

进入并严格确认卖货页后，流程只在卖前读取一次右侧固定区域的载货量 `before_load`。卖出是否成功以**卖出结算报告**为主证据，不使用单像素颜色、卖出总价 OCR、卖出按钮颜色或全选按钮颜色。

1. 读取卖前载货量 `before_load`，例如 `1073 / 1073` 读取为 `1073`。
2. 如果 `before_load == 0`：
   - 记录“车厢为空，无需清货”；
   - 不点出售全部、不议价、不点卖出；
   - 直接视为该城清货完成。
3. 如果 `before_load > 0`：
   - 点击一次“出售全部货物”；
   - 根据路线配置执行议价；
   - 点击一次“卖出”；
   - 等待并最多两次在结算报告主体区域 `(100, 480) → (1180, 610)` 执行局部 OCR。
4. 局部 OCR 命中“卖出结算报告”，或同时命中“总利润”和“纳税/税额”时：
   - 视为卖出成功；
   - 在卖货流程内点击空白区域 `(896, 676)` 关闭结算页；
   - 等待 `0.5` 秒；仅当结算页仍存在时才第二次点击；
   - 返回交易所卖货页，后续由路线流程决定何时离开交易所。
5. 两次结算页 OCR 未命中时，仅在仍明确处于卖货页的前提下执行辅助判断：
   - 若命中“请选择要出售的交易品”，表示本城市没有可出售交易品；保留本地货并成功跳过卖货；
   - `after_load == before_load` 表示“出售全部”没有选中本城可出售的交易品；保留本地货并将清仓步骤视为完成；
   - `after_load < before_load` 仅说明卖出可能已生效，仍须在一次短等待后确认结算报告才可成功；
   - `after_load > before_load`、无法解析，或短等待后仍未确认结算页时，安全失败。
6. 若当前页面既不是卖货页，也不是卖出结算页，直接安全失败，不执行额外固定坐标点击。

注意：在路线开始前的清货失败、以及归位阶段的卖货失败，都会拒绝带货继续后续流程。

## 四、单次端点回合：A 到 B

假设当前城市为 `A`，路线为 `A → B`。

1. 确认/进入 `A` 的买货页。
2. 检查体力；根据配置尝试使用体力药或执行疲劳保护。
3. 按路线配置购买商品：
   - 优先商品先买；
   - 再买次要商品；
   - 商品卡必须是“可购买”才点击；锁定或信息不完整时不点。
4. 单个商品找不到时，商品列表执行：
   - 先用手指“上 → 下”归位到前面的列表顶部；
   - 再用手指“下 → 上”逐屏查看后续商品；
   - 找到即点，到底才停止；不再完整往返扫描。
5. 购买后载货量变为 `0%` 时，立即停止扫描剩余商品，进入买入确认；不会对每个剩余商品重复记录“已满载”。
6. 买入确认前以**本次商品点击后的载货量变化**作为购买清单非空的主证据：
   - 任一商品确认加入后，即使载货量变为 `0%`，也继续议价并点一次“买入”；
   - 未观察到载货量变化时，跳过买入确认，不使用单像素颜色判断；
   - 旧接口 `is_purchase_list_empty()` 只保留兼容，不再作为主流程依据。
7. 买入按钮只点击一次。之后最多两次在 `(100, 480) → (1180, 610)` 进行局部 OCR；命中“买入结算报告”，或同时命中“纳税/税额”和“买入总价”后，在买货流程内关闭结算页。两次均未确认时安全失败，不会重复点击买入。
8. 离开交易所，进入地图并导航到 `B`。
9. 行车监听中仅观察场景和到站，不主动进行交易操作。
10. 到 `B` 后进入卖货页，按“第三节”卖货流程处理。
11. 本次 `A → B` 腿完成。

端点模式的一个“回合”会继续执行反向腿 `B → A`；因此配置为
`运行次数 10` 时，实际会按当前路线模型重复对应的双向/环线路径。

## 五、失败、停止与诊断

以下情况会使当前任务失败而不继续盲点：

- 无法确认买货页或卖货页；
- 买货或卖货关键 OCR 失败；
- 买入或卖出后未能确认对应结算报告；
- 导航失败或行车超时；
- 网络重连耗尽；
- 清货失败且后续可能带着未知货物继续。

失败时会尽力保存运行诊断。诊断包含当时步骤、日志、截图等信息；
如果配置的结束动作是关闭游戏，会执行关闭游戏。

手动点击停止则只停止跑商并保留当前游戏画面，不会按失败路径关闭游戏。

## 六、需要人工验证的重点

以下逻辑已完成静态检查和测试覆盖，但仍应在模拟器中观察：

1. 从卖货页切到买货页时是否只点底部页签。
2. 空车时是否跳过出售全部、议价和卖出。
3. 有可卖货时，是否识别并关闭卖出结算报告。
4. 买入后，是否识别并关闭买入结算报告后再离开交易所。
5. 浏览器最小化再恢复时，日志是否自动补齐。
6. 网络波动加载层、资源更新、每日签到和长期断网的恢复分支是否符合真实 UI。
